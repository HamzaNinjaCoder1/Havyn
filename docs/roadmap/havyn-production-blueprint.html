    1. Vision aur product ka wada

    Havyn ek free desktop app hai. User ek prompt deta hai, aur Havyn Cisco Packet Tracer me poora network banata hai, use ping aur read-back se prove karta hai, aur maujooda networks ki galtiyan dhoondh ke theek karta hai.

    Product ka wada: "Jo network aap bolo, Havyn Packet Tracer me banayega aur prove karega ki woh sach me chalta hai. Jo PT me possible nahi, woh saaf bata dega."

    Kiske liye

    User Unka dard Havyn kya deta hai
    CCNA/CCNP students Labs banane me ghante lagte hain, galti dhoondhna mushkil Prompt se lab, aur galti ki exact wajah
    Teachers aur trainers Har class ke liye naye labs aur broken labs chahiye Seconds me labs, jaan-boojh ke bug wale practice labs
    IT beginners Commands yaad nahi, samajh nahi aata kya toota Aasaan language me samjhana, step-by-step fix
    Lab designers Bade topologies manually banana thakaane wala kaam Bade networks ek prompt se, verified

    Havyn ko alag kya banata hai

    1. Proof, sirf promise nahi. Har build ke baad engine khud config read-back aur ping se prove karta hai. Jo prove nahi hua, woh UNKNOWN likha jata hai, kabhi jhoota PASS nahi.
    2. Live Packet Tracer control. Devices, cables, modules, config, sab asli PT me live hota hai.
    3. Naya bhi, purana bhi. Naya network banana, maujooda network import karna, diagnose karna, theek karna aur behtar karna, sab ek app me.
    4. Poori tarah free aur offline. Havyn ka apna fine-tuned AI model user ke PC pe chalta hai. Koi API key, subscription ya internet zaroori nahi, aur data PC se bahar nahi jata.
    5. Imaandar refusal. Jo PT nahi kar sakta, Havyn usko aadha configure nahi karta, balki saaf wajah batata hai.

    Scope

    Is blueprint me "Cisco" ka matlab Cisco Packet Tracer hai. Asli Cisco hardware ko control karna (SSH ke zariye) is version ka hissa nahi hai.

    2. Na tootne wale niyam

    Yeh 10 niyam Havyn ke har hisse pe lagte hain: engine, AI model, data aur app. Koi feature inme se ek bhi niyam tode, to woh release nahi hoga.

    1. Kabhi jhoota PASS nahi. Verdict hamesha teen hain: PASS, FAIL, UNKNOWN. Jo observe nahi hua, woh UNKNOWN hai.
    2. Command bhejna proof nahi hai. Har badlaav ke baad PT se dobara padh ke (read-back) confirm karo.
    3. Network ka asli proof ping/flow hai. Config sahi dikhna kaafi nahi, traffic chalna chahiye.
    4. Core rules pe, AI kinaare pe. Config banana, push karna, PASS/FAIL tay karna aur safety, sab deterministic rules karte hain. AI sirf user ki baat samajhta hai, intent likhta hai, aur samjhata hai.
    5. AI suggest karta hai, engine prove karta hai. AI ka har fix engine apply karke ping se prove karta hai.
    6. Pehle probe, phir code. Kisi bhi PT API ya CLI ko guess nahi karna.
    7. Jo PT nahi kar sakta, woh saaf refuse ho. Compile ke waqt hi wajah ke saath mana karo. Aadha config kabhi nahi.
    8. Har bug fix ke saath failing-first test. Test fix ke bina fail hona chahiye, aur mutation se uski sensitivity prove honi chahiye.
    9. Offline green ka matlab kaam karta hai nahi. Har feature ka live PT proof chahiye, aur live tests skip hone pe release blocked rehta hai.
    10. Sab kuch free. Har tool, service aur model ka license aisa ho ki Havyn bina kisi kharche ke banaya, chalaya aur baanta ja sake.

    3. Havyn kya karega: 5 capabilities

    Har kaam ka end ek hi hai: PT me live proof ke saath report.

    Capability User kya bolta hai Havyn kya karta hai Kaise prove hota hai
    Create "3 floor ka office, har floor alag VLAN, server room, internet ASA ke through" Intent → plan preview → user confirm → PT me build Saare acceptance criteria + flows PASS
    Diagnose "Mera network khula hai, pc5 server tak nahi pahunch raha" Network import → flows → fault rules → exact root cause Fault ki jagah (device, port, VLAN) evidence ke saath
    Enhance "Is network me guest WiFi alag VLAN pe jod do" Intent diff → sirf naye ops → purana network na toote Naye aur purane, dono criteria PASS
    Explain "Yeh report samjhao" Report aur config ko aasaan language me samjhana Sirf wahi batana jo evidence me hai
    Practice "Mere liye 3 bugs wala lab bana do" Sahi network + jaan-boojh ke bugs → student dhoondhe → Havyn check kare Student ka fix engine prove kare

    Journey 1: Naya network (Create)

    1. User prompt deta hai (English, Roman Urdu, Hinglish, sab chalega).
    2. Kuch zaroori baat missing ho, to Havyn ek ya do sawaal poochhta hai. Baaki ke liye samajhdaar defaults leta hai aur batata hai.
    3. Plan preview: topology diagram, devices, IP plan, VLANs aur acceptance tests. User badal sakta hai.
    4. User "Build" dabata hai. PT me live progress dikhta hai: devices → cables → config → verify.
    5. Report: kya PASS, FAIL ya UNKNOWN, har ek ka saboot. FAIL ho to "Fix" button.
    6. Network .pkt aur spec dono save hote hain, taaki baad me enhance ho sake.

    Journey 2: Maujooda network (Diagnose + Fix)

    1. User PT me apna network kholta hai, ya .pkt file deta hai.
    2. Havyn import karta hai: devices, cables, running-config, IPs.
    3. User batata hai kya chahiye, ya Havyn maqsad ka andaza laga ke confirm karwata hai.
    4. Havyn exact root cause dhoondhta hai: "sw2 ke Gi0/1 trunk pe VLAN 30 allowed nahi".
    5. User "Fix" dabata hai. Havyn sirf zaroori commands bhejta hai, phir ping se prove karta hai.

    Journey 3: Behtar banana (Enhance)

    1. User badlaav bolta hai.
    2. Havyn purane aur naye plan ka diff dikhata hai.
    3. Confirm ke baad sirf badlaav chalte hain, phir poora network dobara verify hota hai.

    4. System architecture

    Havyn ke 6 layer hain. AI sirf upar ke do layer me hai; network banana, push karna aur PASS/FAIL tay karna neeche ke rules wale layer karte hain.

    Intent check fail ho to galti model ko wapas jaati hai (left ka loop). Importer maujooda network ko padh ke usi raaste pe "as-is" intent bhejta hai.

    Layer Zimmedari Free tech
    Desktop App UI, chat, preview, report, wizard, updates Tauri + React
    Havyn Assistant Prompt samajhna, intent likhna, sawaal, samjhana Apna fine-tuned model, GGUF file, llama.cpp server
    Intent check Model ke output ko schema + lint se guzaarna Python (maujooda spec_lint)
    Havyn Engine Expand, compile, execute, verify, diagnose, repair Python network_autopilot (PyInstaller)
    PT Bridge PT se baat, commands, read-back, ping Maujooda mailbox + HTTP transport
    PT + extension Asli network Cisco Packet Tracer (user khud install karta hai) + Havyn script extension

    Ek zaroori faisla: App ek hi local process me engine aur model dono chalati hai. Engine ke 14 MCP tools bhi bane rehte hain, taaki power users Havyn ko doosre MCP clients se bhi chala sakein.

    5. Foundation: engine ko pakka karna

    Koi naya device, AI model ya app feature tab tak shuru nahi hoga jab tak yeh foundation poora na ho. Har device family ka proof ping pe tika hai, aur abhi engine ping ka result padh nahi pa raha.

    Abhi ki asli halat (45-device reference run): structural 87/87, addressing 25/26, L3 3/3 PASS. Lekin flows 0/11 (sab UNKNOWN), L2 3/6, build time 1349 second. Manual ping 10.10.20.7 pe chal gaya (TTL=127), yaani network chalta hai aur engine ka flow reader toota hai.

    ID Kaam Kyun zaroori Done ki shart
    F1 Flow verification theek karo (DHCP gate, parser, timeout, ARP loss) Saare features ka proof isi pe hai 2-VLAN lab pe engine khud ping PASS likhe
    F2 Speed: phase timing, adaptive polling, batching 45 devices 22 minute me ban rahe hain 45-device build 5 minute se kam
    F3 build_havyn.py ke sahi exit codes Scripts fail ko success samajhte hain Failing-first test + live check
    F4 Workspace collision check Ganda workspace wala run 48/124 pe gira Collision pe build na chale, saaf message
    F5 Reconcile-on-reuse ko fix karne wala banao Purani config reuse hoti hai Build ke baad device spec ke barabar
    F6 Galat interface_hint pakdo Routing 100% loss ka kaaran Preflight pe saaf error
    F7 "Route missing" diagnosis rule Repair sirf "interface down" pehchanta hai Fault-injection me sahi diagnosis
    F8 Rollback SafetyGate ke andar, dead code hatao Bina gate ka mutation risk hai Har mutation gate se
    F9 Catalog ka sach (auto-probe) Galat catalog = galat cabling Catalog aur PT me 0 farq
    F10 Ek hi mutation budget ka sach Docs aur code alag Code, docs, tests ek number
    F11 Partial build aur resume Ek run me 134/134 ops blocked Fail wala hissa ruke, baaki chale
    F12 Live test harness pakka Offline green ne dhokha diya Live report ke bina release nahi
    F13 Bache hue L2 aur addressing FAIL Reference run ki asli galtiyan L2 6/6, addressing 26/26
    F14 ASA criteria + address-scoped ACL ka faisla ASA "not exercised" hai ASA flow criterion PASS
    F15 Evidence retention Laptop storage Purane builds apne aap saaf
    F16 Runtime data folder ka naya naam Naya product, purana naam Naye aur purane install dono chalein

    Foundation ka exit gate: reference campus spec 10 me se 10 clean runs me saare acceptance criteria PASS, har run 5 minute se kam, zero manual step, aur sahi exit code.

    6. Device aur feature coverage

    Target: Packet Tracer me jo bhi possible hai, woh Havyn prompt se banaye aur prove kare. Har device family ek alag track hai (poori list section 19 ke Stage 3 me), aur har feature ek hi 8-step tareeke se aata hai.

    Har feature ka 8-step tareeka

    1. Live probe: PT me confirm karo ki API ya CLI se yeh ho sakta hai. Result probes/ me likho.
    2. Schema: intent aur spec me field jodo.
    3. Compiler: sahi config ya JS operations banao.
    4. Push: executor ke zariye PT me bhejo.
    5. Read-back: PT se dobara padh ke confirm karo.
    6. Verify: flow ya criterion se prove karo.
    7. Diagnose + repair rule: is feature ki common galtiyan pakadne aur theek karne ka rule.
    8. Live lab + certification: chhota lab (5 se 15 devices) PT pe PASS, failing-first tests ke saath. Yahi lab baad me AI data ki certification suite banta hai.

    PT Capability Map

    Ek auto-generated table jo har PT device model (152 device types) aur har feature ka status batati hai: Verified (live lab PASS), Unverified (code hai, live proof nahi) ya Refused (PT API nahi deta, wajah ke saath). Yeh map docs aur app dono me dikhega.

    Track Pehle se live-proven Banana hai
    A. Routers Interfaces, subinterfaces, static routes, DHCP pools, extended ACLs OSPF, EIGRP/RIP (ya refuse), NAT/PAT, DHCP relay, HSRP, serial WAN, GRE, IPsec, BGP, IPv6, SSH/AAA, NTP/Syslog/SNMP
    B. Switches VLANs, access ports, trunks, show vlan brief read-back Trunk read-back, L3 SVIs, EtherChannel, STP, port-security, VTP, voice VLAN, management IP
    C. ASA nameif, security-level, IPs, hostname, traversal, wildcard ACL, 5505 read-back Address-scoped ACL faisla, DMZ, ASA NAT, routes, DHCP server, object groups
    D. Servers Static IP aur ping Services API probe, DNS, HTTP, DHCP, Email, FTP, AAA, NTP/Syslog, app-level probe
    E. Wireless WPC300N swap, association, DHCP, Linksys LAN IP AccessPoint-PT, SSID/WPA2 probe, phones/tablets, WLC, multi-SSID VLANs
    F. Modems/Cloud DSL + Cloud auto-mapping, end-to-end ping Cable modem, explicit mapping driver, ISP template, Cloud serial
    G. IoT Cable, IP, ping Registration probe (Server IoT service, Home Gateway), control
    H. End devices PC, laptop Printer, IP phone, phone, tablet, DNS setting

    PT ki jaani limits: ASA ka console nahi milta (getCommandLine() null), to ASA ka proof flows aur port read-back se hoga. Linksys-WRT300N pe SSID, security, WAN type aur DHCP-server ka JS API nahi mila.

    Refusal policy

    Jo cheez probe ke baad bhi PT me possible nahi, woh compile ke waqt refuse ho, error me wajah aur alternative ho ("PT Linksys pe SSID set karne ka API nahi deta; AccessPoint-PT use karein"), aur Capability Map me Refused dikhe.

    7. Maujooda networks: import, diagnose, repair, enhance

    Production ke liye Havyn ko kisi ka bhi bana hua network padhna, uski exact galti batana, kam se kam badlaav se theek karna, aur bina tode behtar karna aana chahiye.

    7.1 Import

    Kya padhna hai Kaise Kami
    Devices, models, positions PT device list API Koi nahi
    Cables aur ports Link/port API Koi nahi
    Port IP, mask, status Port API read-back Koi nahi
    IOS config (routers, switches) Console se show running-config, phir parser Console busy ho to retry
    ASA aur Linksys config Sirf port API aur flows Console nahi milta
    Host settings Host API Koi nahi

    Parser jo line na samjhe, woh chhodi nahi jaati, balki "unparsed" list me dikhti hai. Import ka output ek as-is intent hai, har cheez ke confidence ke saath: known, partial ya unknown.

    7.2 Diagnose

    1. Maqsad tay karo: user batata hai, ya Havyn andaza laga ke confirm karwata hai.
    2. Flows chalao: fail maqsad hi shuruaati point hain.
    3. Raasta trace karo: gateway, ARP, VLAN, trunk allowed list, routes, ACL, NAT, har hop.
    4. Layer order me rules: L1 → L2 → L3 → policy → services.
    5. Result: root cause, device aur port, saboot, confidence, fix plan. Evidence kam ho to "UNKNOWN, yeh check karo".

    7.3 Repair

    • Maujooda network pe default mode APPROVAL_REQUIRED.
    • Fix se pehle backup: .pkt copy aur running-configs.
    • Sirf zaroori commands, phir poora network dobara verify.
    • Kuch aur toote to automatic rollback, SafetyGate ke andar.

    7.4 Enhance

    Intent diff → conflicts (IP overlap, VLAN takraav, ports khatam, naming clash) → preview → sirf diff ke ops → poora verify.

    Accuracy: fault-injection benchmark se naapi jayegi. Target: sahi root cause 90% ya zyada, galat fix 0.

    8. Havyn AI model

    Havyn ka apna fine-tuned model user ke PC pe offline chalega. Model sirf samajhta, likhta aur samjhata hai. Network banana, commands bhejna aur PASS/FAIL tay karna engine ka kaam hai.

    Kaam Input Output
    Intent User ka prompt Chhota intent JSON
    Sawaal Adhoora prompt 1 ya 2 zaroori sawaal, ya "sawaal ki zaroorat nahi"
    Enhance Purana intent + badlaav Intent patch (sirf farq)
    Diagnosis samjhana Engine ki evidence Root cause, jagah, fix suggestion, aasaan explanation
    Explain / tutor Report, config ya sawaal Aasaan zabaan me, sirf evidence ke hisaab se

    Model kya kabhi nahi karega: seedhe PT commands bhejna, PASS/FAIL likhna, ya safety gate bypass karna.

    8.1 Intent layer

    Model poora spec nahi likhta, ek chhota intent likhta hai. Engine ka expander IPs (IPAM), ports (port solver), positions (layout) aur cables khud banata hai. Intent v1 ke fields: sites, floors_or_areas, hosts, vlans, servers, routing, internet, firewall, wireless, iot, requirements, constraints.

    8.2 Output ki guarantee

    1. Schema-bound decoding: llama.cpp sirf valid intent JSON likhne deta hai.
    2. Self-correction loop: schema + spec_lint + compile check, galti ho to error model ko wapas, max 3 koshish, phir user se sawaal.
    3. Capability map context me: unsupported cheez pe model mana kare.
    4. Plan preview: build se pehle user confirm kare.

    9. Training data pipeline

    Data dhoondha nahi jayega, Havyn ke engine se banaya jayega. Pehle jawab (sahi network) banta hai, phir sawaal (prompt). Har generator rule pehle live PT pe prove hota hai.

    Audit me ek bhi fail ho to us rule ka poora data rukta hai, rule theek hota hai aur dobara certify hota hai.

    9.1 Certification

    Component Cases PT pe kya prove ho
    Har archetype Min, normal, max size Build + criteria + flows PASS
    Har feature Akela + combination Feature checks PASS
    Har fault injector 5 networks Bug flow tode, evidence me dikhe, fix se wapas PASS
    Har mutation 3 cases Badlaav ke baad bhi PASS
    Healthy 5 cases Koi fault nahi

    Certificate ek chhota JSON hai (component, generator version, engine commit, cases, passed, date). Code badle to certificate apne aap expire.

    9.2 Data ke sources

    Source Kaise v1 me
    Naya network Intent generator → compile + lint → prompt (30% templates, 70% open teacher model) ~5,000
    Diagnosis Program se bug → evidence → label injector se ~2,000
    Enhance Mutation → dono compile → label = JSON patch ~1,000
    Sawaal Zaroori fields hatao → sahi sawaal ~500
    Gold test Aap aur dost khud likhein ~300 (training me kabhi nahi)
    User feedback Release ke baad, ijazat se Har version me

    9.3 Saat quality filters

    1. Schema. 2. Engine lint + compile. 3. Round-trip (doosri model family se intent wapas). 4. Duplicate (MinHash). 5. Coverage balance. 6. Insaani check (2-5%). 7. Live audit.

    9.4 Bias aur overfit se bachav

    • Coverage matrix: har combination me kam se kam 30 examples, aur ek upper limit.
    • Diagnosis slices: healthy ~15%, UNKNOWN ~10%, do bug ~10%, same-evidence cases ka label "X ya Y".
    • Enhance: ~10% impossible requests (sahi jawab: mana). Sawaal: ~40% "sawaal nahi poochhna".
    • Split: train ~85%, validation ~10%, held-out archetype ~5%, archetype/template family ke hisaab se; leakage check aur dataset card.

    9.5 Kaggle aur laptop

    8 Kaggle notebooks, har ek ka output ek versioned Kaggle Dataset (havyn-intents-vN se havyn-train-vN tak), Hugging Face pe backup. Laptop pe sirf PT wala kaam ek runner karta hai (queue, saaf workspace, resume, upload, prune). Laptop pe pipeline 1 GB se kam jagah.

    14. Security, privacy aur safety

    Area Niyam
    Network exposure Sab services sirf 127.0.0.1, random token

    21.3 Model apni peak pe

    1. Pehli run ka benchmark: GPU VRAM, RAM aur CPU cores dekh ke best settings chuno aur save karo: GPU layers, threads (physical cores ke barabar), batch size.
    2. Sahi quantization: VRAM ke hisaab se Q4_K_M, Q5_K_M ya Q8_0. Har quant release gates (section 10) pe alag se test hota hai; jo gate fail kare, woh ship nahi hota.
    3. Chhota context: intent layer ki wajah se lamba context nahi chahiye. Kam memory, zyada speed.
    4. KV cache quantization aur flash attention: jahan backend support kare, benchmark se on/off.
    5. Model garam rakho: app khulte hi background me load; system prompt aur schema ka prompt cache.
    6. Speculative decoding: Lite ko Standard ka draft model banao. Sirf tab on, jab benchmark tez dikhaye aur output bilkul same rahe.
    7. Schema-bound decoding: chhota aur hamesha valid output, dobara koshish kam.
    8. Fallback ki seedhi: memory kam pade to kam GPU layers → Lite model → sirf CPU. Har kadam pe user ko saaf message.
    Hardware tier Example Target
    Chhota 8 GB RAM, sirf CPU Lite: intent 60 second se kam
    Beech ka 16 GB RAM, 4-6 GB GPU Standard: intent 20 second se kam
    Bada 32 GB RAM, 8 GB+ GPU Standard: intent 10 second se kam

    Teeno tiers har release se pehle naape jaate hain; koi target toote to release rukti hai.

    21.4 Release pipeline

    1. Version tag (semantic versioning).
    2. GitHub Actions (Windows runner): engine sidecar, llama.cpp CPU build, Tauri app, MSIX aur installer.
    3. Size budget check aur offline tests.
    4. Installer smoke test runner pe: install, app start, engine health, uninstall.
    5. Checksums, SBOM aur release notes.
    6. Laptop se taaza live regression report attach.
    7. Pehle beta channel, phir stable: Microsoft Store, GitHub Releases, winget.

    21.5 Updates bina tode

    • Do channels: beta aur stable. Har naya version pehle beta me.
    • App aur model alag update: model badle bina app update, app badle bina model.
    • Rollback: update fail ho to purana version wapas.
    • Migration test: har release me purane settings aur projects naye version me khulein.
